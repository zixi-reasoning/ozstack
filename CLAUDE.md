## What this repository is

`兔狲大力玩` is a static VitePress site for two Chinese technical books by 籽溪. The repository slug and GitHub Pages base remain `ozstack` so old links keep working; the visible brand is `兔狲大力玩`. Do not rename the repository or Pages base without the owner's approval.

- `《古法编程大力玩》` builds Aletheia, a 256 KiB machine made from one static array, across four volumes and about 40 chapters.
- `《计算科学大力丸》` uses the same machine as a computational-science laboratory across four volumes and 40 chapters.

Both books share the same machine, instruction set, and character-only teletype output. Book pages are strict Markdown and LaTeX; the homepage is the main place where raw HTML and custom CSS are used.

At the time of writing, each book has only its `introduction` chapter. The remaining chapter folders and `books.mjs` entries still need to be added.

## Commands

```bash
npm install
npm run docs:dev                         # local dev server, http://localhost:5173
npm run docs:build                       # build with base /
DOCS_BASE=/ozstack/ npm run docs:build   # production-equivalent build
npm run docs:preview                     # preview the built site
```

There are no test or lint scripts. The production build is the verification gate. Build output goes to `docs/.vitepress/dist/`.

CI uses Node 24 and `npm ci`; see `.github/workflows/deploy.yml`. Pushes to `main` build and deploy to GitHub Pages at `https://zixi-reasoning.github.io/ozstack/`.

## Architecture

VitePress reads `docs/` as the content root. `docs/.vitepress/config.mts` is the site config:

- `base` comes from `DOCS_BASE`, defaulting to `/` locally and `/ozstack/` in CI.
- `markdown.math` enables MathJax.
- Nav, sidebar, local search, outline levels, and Chinese UI labels are defined here.
- `appearance: false` keeps the site in the light theme.

`docs/.vitepress/books.mjs` is the single source of book metadata and chapter navigation. `BOOKS` contains each book's `value`, `no`, `label`, `base`, `start`, and `chapters`. `sidebarFor()` turns a book's chapters into a VitePress sidebar. `config.mts` imports `BOOKS` and `sidebarFor`, so adding a chapter means adding a folder plus one entry in `books.mjs`; do not maintain a second sidebar list.

The two books have no standalone landing pages. Each `start` points directly at its introduction:

- `/gufa/introduction/`
- `/jisuan/introduction/`

The right-hand outline is generated by VitePress from page headings. The homepage is `docs/index.md`; it uses the custom `oz-links` and `oz-features` classes from `docs/.vitepress/theme/custom.css`.

`docs/.vitepress/theme/index.js` extends VitePress's DefaultTheme and loads `custom.css`. The custom theme implements the paper, green, and halftone visual system plus the Chomsky masthead font. Public assets live under `docs/public/`.

Typical chapter layout:

```text
docs/<book>/<english-slug>/index.md
```

Chapter folders use lowercase English slugs. Add the chapter to `BOOKS[].chapters` as `{ text: '...', link: '/<book>/<english-slug>/' }`.

## Content rules

These are project constraints, not style suggestions:

- Book content uses pure Markdown and LaTeX. Do not add Vue components or VitePress `:::` containers to book pages.
- No images, screenshots, charts, Mermaid, or ASCII art in the books. Output is text only.
- Math must use `$...$` inline and `$$...$$` display. Do not use `\(...\)` or `\[...\]`.
- Do not use Chinese or English em dashes in book content.
- All complete code belongs inline in the chapter Markdown. Do not create separate `.c` files, `docs/public/code`, or download links. The first line of each code block names a suggested filename, for example `/* aletheia-map.c */`.
- Aletheia is a closed machine: one static 256 KiB array, no libc, no libm, no dynamic linker, no second runtime. `AletheiaC` interprets a C subset inside the machine, without a host compiler.
- The second book separates proof from evidence. Finite experiments are witnesses, not proofs; records must state precision, seed, step limit, memory limit, and status.

## Repository gotchas

- `.gitignore` contains `.vitepress/`, which also matches `docs/.vitepress/`. The existing config and theme files are tracked, but `git add docs/.vitepress/...` can refuse them as ignored. Stage edits to tracked files with `git add -u docs/.vitepress/...`. New files under `docs/.vitepress/` are ignored by default; do not force-add ignored files without checking whether they are private.
- The repo name and Pages base are still `ozstack`. The visible site name is `兔狲大力玩`. Renaming the repository or `DOCS_BASE` breaks existing URLs.
- Do not add agent attribution or `Co-Authored-By` trailers to commits. The owner does not want agent names in the Git history.
- Keep ignored files out of commits and pushes. Some local files are intentionally private; never use `git add -f` to publish them.

## Verification checklist

For content or config changes:

1. Run `DOCS_BASE=/ozstack/ npm run docs:build`.
2. Check the relevant page under `docs/.vitepress/dist/` for rendered HTML and math.
3. Confirm no images, `:::`, `\(...\)`, or em dashes were introduced into book content.
